Colecciones y JSON

El testing es, en gran parte, manejar datos: listas de elementos, diccionarios con la respuesta de una API, y JSON yendo y viniendo. Estas estructuras son el pan de cada día.

Listas y diccionarios

La lista es una secuencia ordenada y mutable (items[0], items[-1], len(items)). El diccionario mapea claves a valores (order["status"]) y es el reflejo natural de un objeto JSON. Las tuplas son inmutables y los sets descartan duplicados.

Python 
# Las listas (ordenadas, mutables) y los dicts (clave -> valor) son tu día a día.
items = ["book", "pen", "mug"]
items.append("lamp")
print(items[0], items[-1], len(items))   # book lamp 4

order = {"id": 42, "status": "PAID", "total": 250}
print(order["status"])                   # PAID
order["status"] = "REFUNDED"             # actualizá un valor
print("total" in order)                  # True

# Las tuplas son inmutables; los sets descartan duplicados.
point = (10, 20)
unique = set([1, 1, 2, 3])               # {1, 2, 3}# Lists (ordered, mutable) and dicts (key -> value) are your daily tools.
items = ["book", "pen", "mug"]
items.append("lamp")
print(items[0], items[-1], len(items))   # book lamp 4

order = {"id": 42, "status": "PAID", "total": 250}
print(order["status"])                   # PAID
order["status"] = "REFUNDED"             # update a value
print("total" in order)                  # True

# Tuples are immutable; sets drop duplicates.
point = (10, 20)
unique = set([1, 1, 2, 3])               # {1, 2, 3}

Comprehensions

Una comprehension construye una lista o diccionario en una línea legible, con filtro opcional. Combinada con all(...) y any(...) es ideal para afirmar sobre toda una colección ("todos los precios son positivos").

Python 
# Una comprensión construye una colección en una línea legible.
prices = [10, 25, 7, 50]
with_tax = [round(p * 1.21, 2) for p in prices]   # [12.1, 30.25, 8.47, 60.5]
expensive = [p for p in prices if p > 20]         # [25, 50]

# Comprensión de dict: id -> name
users = [{"id": 1, "name": "Ada"}, {"id": 2, "name": "Grace"}]
by_id = {u["id"]: u["name"] for u in users}       # {1: "Ada", 2: "Grace"}

# any() / all() se leen como en inglés en asserts sobre una colección.
assert all(p > 0 for p in prices)# A comprehension builds a collection in one readable line.
prices = [10, 25, 7, 50]
with_tax = [round(p * 1.21, 2) for p in prices]   # [12.1, 30.25, 8.47, 60.5]

# Dict comprehension: id -> name

# any() / all() read like English in assertions over a collection.
assert all(p > 0 for p in prices)

JSON

Las APIs hablan JSON. El módulo json convierte texto JSON a dict/list con json.loads y de vuelta con json.dumps. En la práctica, requests ya te devuelve el body parseado con response.json().

Python 
# Las APIs hablan JSON; el módulo json lo mapea a dicts/lists y viceversa.
import json

raw = '{"id": 42, "items": ["book"], "total": 250}'
order = json.loads(raw)        # texto JSON -> dict
print(order["items"][0])       # book

# dict -> texto JSON (indent hace legibles los diffs de los tests)
payload = json.dumps({"status": "PAID"}, indent=2)

# requests hace esto por vos: response.json() devuelve el body parseado.# APIs speak JSON; the json module maps it to dicts/lists and back.

print(order["items"][0])       # book

# dict -> JSON text (indent makes test diffs readable)
payload = json.dumps({"status": "PAID"}, indent=2)

# requests does this for you: response.json() returns the parsed body.
