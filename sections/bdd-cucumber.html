Cucumber y step definitions

Gherkin describe qué probar; los step definitions dicen cómo. Cucumber es la herramienta que conecta cada paso en lenguaje natural con el código que lo ejecuta (el "glue"). Existe para casi todos los lenguajes.

Cucumber.js (con Playwright)

En JS/TS usás @cucumber/cucumber: registrás Given/When/Then con la frase exacta del paso y el código que la implementa (acá, con Playwright). Los {string} capturan valores del paso y llegan como argumento.

JavaScript 
// steps/checkout.steps.js — el "pegamento" que mapea cada paso de Gherkin a acciones.
const { Given, When, Then } = require("@cucumber/cucumber");
const { expect } = require("@playwright/test");

Given("I have a book in my cart", async function () {
  await this.page.goto("/cart?items=book");
});

When("I pay with a valid card", async function () {
  await this.page.getByRole("button", { name: "Pay" }).click();
});

// {string} captura el valor entre comillas del paso y lo pasa como argumento.
Then("the order status should be {string}", async function (status) {
  await expect(this.page.locator(".order-status")).toHaveText(status);
});// steps/checkout.steps.js — "glue" that maps each Gherkin step to actions.

pytest-bdd (con Python)

En Python, pytest-bdd (o behave) hace lo mismo: scenarios("checkout.feature") ata los escenarios del archivo y decorás funciones con @given/@when/@then. Reusás toda la potencia de pytest (fixtures, parametrize).

Python 
# test_checkout.py — el mismo feature conectado con pytest-bdd.
from pytest_bdd import scenarios, given, when, then
from playwright.sync_api import Page, expect

scenarios("checkout.feature")   # vincula cada escenario del archivo


@given("I have a book in my cart")
def add_book(page: Page):
    page.goto("/cart?items=book")


@when("I pay with a valid card")
def pay(page: Page):
    page.get_by_role("button", name="Pay").click()


@then('the order status should be "PAID"')
def status_paid(page: Page):
    expect(page.locator(".order-status")).to_have_text("PAID")# test_checkout.py — the same feature wired up with pytest-bdd.

Tip: mantené los step definitions finos — que llamen a Page Objects o helpers, no que tengan lógica de test adentro. Steps reutilizables = features que escalan.
