Tu primer componente testeado

Hora de juntar todo: tu primer test "de verdad". Primero contra una API con requests + pytest, y después contra una UI real con Playwright. Mismo patrón, dos mundos.

Testeando una API

Un test de API no necesita navegador: pegás al endpoint, verificás el status y la forma de la respuesta. Es la forma más rápida de empezar a automatizar de verdad.

Python 
# test_orders_api.py — tu primer test real: pegale a una API, verificá el contrato.
import requests

BASE = "https://api.example.com"


def test_order_42_is_paid():
    res = requests.get(f"{BASE}/orders/42", timeout=10)

    # Primero el status, después la forma del body.
    assert res.status_code == 200
    body = res.json()
    assert body["status"] == "PAID"
    assert body["total"] == 250
    assert "book" in body["items"]# test_orders_api.py — your first real test: hit an API, check the contract.
import requests

BASE = "https://api.example.com"


def test_order_42_is_paid():
    res = requests.get(f"{BASE}/orders/42", timeout=10)

    # Status first, then the body's shape.
    assert res.status_code == 200
    body = res.json()
    assert body["status"] == "PAID"
    assert body["total"] == 250
    assert "book" in body["items"]

Testeando un componente de UI

El mismo patrón Arrange-Act-Assert, ahora contra el navegador con Playwright. Las web-first assertions (expect(...).to_be_visible()) esperan solas, así que tu primer test de UI ya nace sin flakiness.

Python 
# test_login_ui.py — la misma idea contra un browser real, con Playwright.
from playwright.sync_api import Page, expect


def test_login_greets_the_user(page: Page):
    page.goto("https://example.com/login")
    page.get_by_label("Username").fill("demo")
    page.get_by_label("Password").fill("secret")
    page.get_by_role("button", name="Sign in").click()

    # Aserción web-first: auto-espera hasta que aparezca el texto o se agote el tiempo.
    expect(page.get_by_text("Welcome, demo")).to_be_visible()# test_login_ui.py — the same idea against a real browser, with Playwright.

Manual vs AI

Manual A mano

Aprendés la sintaxis y escribís cada test paso a paso. Es la mejor forma de entender qué hace cada línea antes de delegar nada.

Con AI Con AI

Una vez que entendés las bases, la AI acelera: genera el esqueleto del test en Python, sugiere casos y explica errores. Vos revisás y decidís qué entra al repo.

Próximo paso: con Python y pytest dominados, elegí Selenium o Playwright en la navegación y construí suites completas. Ya tenés la base.
