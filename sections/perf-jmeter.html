Performance

JMeter

Apache JMeter es el clásico de la industria: maduro, con interfaz gráfica y un enorme ecosistema de plugins. Armás el plan de prueba en la GUI y lo corrés sin interfaz en CI.

Un plan se estructura en Thread Group (los usuarios virtuales), Samplers (las requests), Assertions (pasa/falla) y Listeners (resultados). Para CI, lo corrés en modo non-GUI (-n) y generás un reporte HTML.

Bash 
# JMeter: armá el plan en la GUI, después corrélo headless (-n) en CI.
# Un plan es: Thread Group (usuarios virtuales) -> Samplers (requests) ->
# Assertions (pass/fail) -> Listeners (resultados).

# Corré un plan .jmx guardado, escribí resultados crudos, después un dashboard HTML:
jmeter -n -t orders-load.jmx -l results.jtl -e -o report/

# -n sin GUI  ·  -t plan  ·  -l resultados  ·  -e -o arma el reporte HTML# JMeter: build the plan in the GUI, then run it headless (-n) in CI.
# A plan is: Thread Group (virtual users) -> Samplers (requests) ->
# Assertions (pass/fail) -> Listeners (results).

# Run a saved .jmx plan, write raw results, then an HTML dashboard:
jmeter -n -t orders-load.jmx -l results.jtl -e -o report/

# -n non-GUI  ·  -t plan  ·  -l results  ·  -e -o build the HTML report
Tip: usá la GUI solo para armar y depurar el plan; nunca para correr la carga real (consume recursos y falsea los números). La carga seria siempre va en modo -n por línea de comandos.
