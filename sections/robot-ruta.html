Ruta de aprendizaje

Ruta de aprendizaje

  1. Keywords y estructura — El corazón de Robot: encadenás keywords y creás los tuyos en *** Keywords ***.
  2. Localizar elementos — Locators estilo "strategy=value": id=, css=, xpath=. Preferí id/css.
  3. Esperas explícitas — Wait Until… en vez de Sleep: esperá la condición, no el reloj.
  4. APIs con RequestsLibrary — Create Session + GET/POST/PATCH/DELETE On Session, sin navegador.
  5. Resource files (POM) y CI — Resource files como Page Objects; robot --variable y --outputdir en CI.

Keywords y estructura

Un test es una lista de keywords. Las traés de una librería (Library SeleniumLibrary) o creás los tuyos en la sección *** Keywords *** con [Arguments]. Las variables viven en *** Variables *** y se usan como ${VAR}. Encapsular flujos en keywords propios es lo que hace la suite legible y mantenible.

Robot Framework 
*** Settings ***
Library    SeleniumLibrary

*** Variables ***
${LOGIN_URL}    https://example.com/login

*** Test Cases ***
Valid login
    Login With    demo    secret           # llamá a tu propia keyword
    Page Should Contain    Welcome, demo

*** Keywords ***
Login With
    [Arguments]    ${user}    ${pass}       # una keyword de usuario reutilizable
    Open Browser    ${LOGIN_URL}    chrome
    Input Text      id=username    ${user}
    Input Text      id=password    ${pass}
    Click Button    Sign in*** Settings ***

Localizar elementos

Con SeleniumLibrary los locators usan la forma estrategia=valor: id=submit, css=.order-total, xpath=//button[...]. Las acciones (Click Button, Input Text) y las aserciones (Element Should Be Visible, Element Text Should Be) son todas keywords. Regla: preferí id/css sobre xpath.

Robot Framework 
# Los locators de SeleniumLibrary usan la forma "strategy=value". Preferí id/css antes que xpath.
Click Button     id=submit                      # por id
Input Text       css=.search    book            # por CSS
Click Element    xpath=//button[text()='Pay']   # por texto visible

# Las aserciones también son keywords:
Element Should Be Visible    css=.welcome
Element Text Should Be       css=.order-status    PAID# SeleniumLibrary locators use a "strategy=value" form. Prefer id/css over xpath.
Click Button     id=submit                      # by id
Input Text       css=.search    book            # by CSS
Click Element    xpath=//button[text()='Pay']   # by visible text

# Assertions are keywords too:
Element Should Be Visible    css=.welcome
Element Text Should Be       css=.order-status    PAID

Esperas explícitas

Como en Selenium, nunca uses un Sleep fijo: es la causa número uno de flakiness. Usá los keywords Wait Until Element Is Visible, Wait Until Page Contains o Wait Until Element Is Enabled con un timeout. Esperás la condición, no un tiempo arbitrario.

Robot Framework 
# Esperá una CONDICIÓN, nunca un Sleep fijo (la causa #1 de suites inestables).
Wait Until Element Is Visible    css=.welcome    timeout=5s
Wait Until Page Contains         Welcome, demo   timeout=5s
Wait Until Element Is Enabled    id=pay

# Evitá esto:
# Sleep    5s# Wait for a CONDITION, never a fixed Sleep (the #1 cause of flaky suites).
Wait Until Element Is Visible    css=.welcome    timeout=5s
Wait Until Page Contains         Welcome, demo   timeout=5s
Wait Until Element Is Enabled    id=pay

# Avoid this:
# Sleep    5s

APIs con RequestsLibrary

Para testear APIs sin navegador usás RequestsLibrary: abrís una sesión con Create Session y disparás GET/POST/PATCH/DELETE On Session. Verificás el status con Status Should Be (o el parámetro expected_status) y la forma del body con Should Be Equal As Strings. Mismo contrato CRUD que en los otros frameworks.

Robot Framework 
*** Settings ***
Library    RequestsLibrary

*** Test Cases ***
Read an order over HTTP
    Create Session    api    https://api.example.com
    ${res}=    GET On Session    api    /orders/42
    Status Should Be    200    ${res}
    Should Be Equal As Strings    ${res.json()}[status]    PAID

Resource files (POM) y CI

El Page Object Model en Robot son los resource files: archivos .resource con keywords compartidos que importás con Resource. Encapsulás selectores y acciones de una página en un solo lugar. En CI corrés robot --variable BROWSER:headlesschrome --outputdir results tests/ y publicás el report.html.

Robot Framework 
# orders.resource — un "resource file" es el Page Object de Robot: keywords compartidas.
*** Keywords ***
Open Order
    [Arguments]    ${id}
    Go To    https://shop.example.com/orders/${id}

Order Total Should Be
    [Arguments]    ${expected}
    Element Text Should Be    css=.order-total    ${expected}

# En un test:  Resource    orders.resource    y después llamá a esas keywords.
# En CI:  robot --variable BROWSER:headlesschrome --outputdir results tests/# orders.resource — a "resource file" is Robot's Page Object: shared keywords.
*** Keywords ***
Open Order
    [Arguments]    ${id}
    Go To    https://shop.example.com/orders/${id}

Order Total Should Be
    [Arguments]    ${expected}
    Element Text Should Be    css=.order-total    ${expected}
