Git para QA

Tus tests son código: viven en un repositorio y se revisan como cualquier cambio. Git es la herramienta de versionado estándar — sin ella no colaborás ni te integrás a un pipeline de CI.

El flujo básico

El ciclo de todos los días: clone el repo, creás una branch propia (nunca toques main directo), hacés add + commit con un mensaje claro y push. Un buen mensaje de commit explica el por qué, no solo el qué.

Bash 
# Conseguí el código y trabajá en tu propia rama (nunca hagas commit directo a main).
git clone https://github.com/acme/shop-e2e.git
git checkout -b feature/login-tests   # creá + cambiá a una rama nueva

git add tests/login.spec.ts           # prepará tus cambios
git commit -m "test: add login happy path"
git push -u origin feature/login-tests# Get the code and work on your own branch (never commit straight to main).
git clone https://github.com/acme/shop-e2e.git
git checkout -b feature/login-tests   # create + switch to a new branch

git add tests/login.spec.ts           # stage your changes
git commit -m "test: add login happy path"
git push -u origin feature/login-tests

Actualizar y resolver conflictos

Antes de abrir un PR, traés lo último de main con pull --rebase. Si hay un conflicto, editás el archivo, git add y git rebase --continue (o --abort para volver atrás). git stash te guarda cambios a medio hacer para cambiar de tarea sin commitear.

Bash 
# Mantené tu rama al día y resolvé los conflictos con calma.
git pull --rebase origin main         # reaplicá tus commits sobre main

# Si el rebase encuentra un conflicto: editá el archivo, después:
git add tests/login.spec.ts
git rebase --continue                 # o: git rebase --abort para abandonar

# Guardá el trabajo en curso para cambiar de tarea sin hacer commit:
git stash            # guardá los cambios
git stash pop        # traelos de vuelta# Keep your branch current and resolve conflicts calmly.
git pull --rebase origin main         # replay your commits on top of main

# If the rebase hits a conflict: edit the file, then:
git add tests/login.spec.ts
git rebase --continue                 # or: git rebase --abort to bail out

# Park work-in-progress to switch tasks without committing:
git stash            # save changes
git stash pop        # bring them back
Regla de oro: commits chicos y frecuentes, branches por feature, y nunca reescribas la historia de una branch compartida con --force salvo que sepas exactamente lo que hacés.
