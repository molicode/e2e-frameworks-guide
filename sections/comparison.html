Comparativa

Nada explica mejor las diferencias que el mismo test en los tres frameworks. Resolvemos el caso VerifyOrder y observamos cómo cada uno maneja los assertions y las esperas.

Caso “VerifyOrder”: en la página de una orden, verificar que total = 250, que status = PAID y que la lista de items contiene book. Mismo objetivo, tres estilos.
Selenium

Selenium: leés cada valor con getText() y comparás con assert a mano. Más verboso y tenés que pensar las esperas.

Python 
# VerifyOrder — Selenium WebDriver (Python)
from selenium import webdriver
from selenium.webdriver.common.by import By

driver = webdriver.Chrome()
driver.get("https://shop.example.com/orders/42")

# Leé cada valor primero, luego afirmá a mano.
total = driver.find_element(By.CSS_SELECTOR, ".order-total").text
status = driver.find_element(By.CSS_SELECTOR, ".order-status").text
items = driver.find_elements(By.CSS_SELECTOR, ".order-items li")
texts = [el.text for el in items]

assert total == "250"
assert status == "PAID"
assert any("book" in t for t in texts)

driver.quit()# VerifyOrder — Selenium WebDriver (Python)

Cypress

Cypress: .should() encadenado, con auto-retry. Conciso y legible; las esperas son implícitas.

TypeScript 
// VerifyOrder — Cypress con TypeScript
cy.visit("https://shop.example.com/orders/42");

// Cada .should() reintenta automáticamente hasta que pasa o se agota el tiempo.
cy.get(".order-total").should("have.text", "250");
cy.get(".order-status").should("have.text", "PAID");
cy.get(".order-items li").should("contain", "book");// VerifyOrder — Cypress with TypeScript
cy.visit("https://shop.example.com/orders/42");

// Each .should() retries automatically until it passes or times out.
cy.get(".order-total").should("have.text", "250");
cy.get(".order-status").should("have.text", "PAID");
cy.get(".order-items li").should("contain", "book");
Playwright

Playwright: expect(...) web-first que auto-espera. Conciso, explícito en la intención y multi-navegador.

Python 
# VerifyOrder — pytest-playwright
from playwright.sync_api import Page, expect


def test_verify_order(page: Page):
    page.goto("https://shop.example.com/orders/42")

    # Las aserciones web-first auto-esperan y reintentan — sin lecturas manuales.
    expect(page.locator(".order-total")).to_have_text("250")
    expect(page.locator(".order-status")).to_have_text("PAID")
    expect(page.locator(".order-items li")).to_contain_text("book")# VerifyOrder — pytest-playwright

Robot Framework

Robot Framework: keyword-driven — cada paso es un keyword legible (Element Text Should Be). El más fácil de leer; por debajo usa Selenium o Playwright.

Respuesta

Según el lenguaje del equipo, los navegadores objetivo, el tipo de app y la DX; no hay uno “mejor” universal.

Playwright (Chromium, Firefox, WebKit) y Selenium (vía WebDriver).

Cypress (runner visual, time-travel) y Playwright (trace viewer).

Selenium o Playwright (ambos con bindings de Python).
