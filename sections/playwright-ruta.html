Locators y acciones

Los locators son perezosos: describen cómo encontrar un elemento y se resuelven al actuar o afirmar. Preferí queries centradas en el usuario: get_by_role, get_by_label, get_by_text. Refinás listas con .filter(), indexás con .nth()/.first/.last y encadenás para llegar al elemento exacto.

Python 
# Los locators son lazy: describen CÓMO encontrar un elemento y se resuelven
# en el momento en que actuás o aseverás. Preferí consultas orientadas al usuario.
page.get_by_role("button", name="Sign in").click()
page.get_by_label("Email").fill("demo@acme.test")
page.get_by_text("Welcome").click()

# Filtrá y acotá listas:
rows = page.get_by_role("row")
rows.filter(has_text="book").get_by_role("button", name="Remove").click()

# Indexá una lista con .nth() (base 0), o .first / .last:
page.locator(".order-items li").nth(2).click()
expect(page.locator(".order-items li")).to_have_count(3)# Locators are lazy: they describe HOW to find an element and resolve
# at the moment you act or assert. Prefer user-facing queries.
page.get_by_role("button", name="Sign in").click()
page.get_by_label("Email").fill("demo@acme.test")
page.get_by_text("Welcome").click()

# Filter and narrow down lists:
rows = page.get_by_role("row")
rows.filter(has_text="book").get_by_role("button", name="Remove").click()

# Index into a list with .nth() (0-based), or .first / .last:
page.locator(".order-items li").nth(2).click()
expect(page.locator(".order-items li")).to_have_count(3)

Assertions y auto-waiting

Las web-first assertions (expect(locator).to_have_text(...), to_be_visible(), to_have_count()) reintentan solas hasta cumplirse o expirar. Por eso casi nunca esperás a mano. Para valores que no son del DOM, un assert común no reintenta.

Python 
# Las aserciones web-first reintentan hasta pasar o alcanzar el timeout.
# Casi nunca esperás de forma manual.
expect(page.get_by_role("heading")).to_have_text("Order #42")
expect(page.locator(".order-status")).to_have_text("PAID")
expect(page.locator(".order-items li")).to_have_count(3)
expect(page.get_by_test_id("pay-btn")).to_be_disabled()

# Un assert simple es para valores no-DOM (no reintenta):
assert 1 + 1 == 2

# ¿Necesitás un estado específico? Esperá la CONDICIÓN, no un sleep:
page.get_by_role("button", name="Pay").click()
expect(page.get_by_text("Payment confirmed")).to_be_visible()# Web-first assertions auto-retry until they pass or hit the timeout.
# You almost never wait manually.
expect(page.get_by_role("heading")).to_have_text("Order #42")
expect(page.locator(".order-status")).to_have_text("PAID")
expect(page.locator(".order-items li")).to_have_count(3)
expect(page.get_by_test_id("pay-btn")).to_be_disabled()

# A plain assert is for non-DOM values (it does not retry):
assert 1 + 1 == 2

# Need a specific state? Wait for the CONDITION, not a sleep:
page.get_by_role("button", name="Pay").click()
expect(page.get_by_text("Payment confirmed")).to_be_visible()

Fixtures y organización

Para que la suite escale: usá fixtures de pytest (en conftest.py) para el setup, encapsulá páginas en un Page Object y exponelo como una fixture propia con @pytest.fixture. Así cada test recibe justo lo que necesita y queda limpio y legible.

Python 
# order_page.py — un Page Object encapsula selectores + acciones.
class OrderPage:
    def __init__(self, page):
        self.page = page
        self.total = page.locator(".order-total")
        self.status = page.locator(".order-status")

    def goto(self, order_id):
        self.page.goto(f"/orders/{order_id}")


# conftest.py — exponé el Page Object como una fixture.
import pytest
from order_page import OrderPage


@pytest.fixture
def order_page(page):
    return OrderPage(page)


# test_order.py — la fixture mantiene los tests limpios.
from playwright.sync_api import expect


def test_verify_order(order_page):
    order_page.goto(42)
    expect(order_page.total).to_have_text("250")
    expect(order_page.status).to_have_text("PAID")# order_page.py — a Page Object encapsulates selectors + actions.
class OrderPage:

        self.total = page.locator(".order-total")

Network y auth

Con page.route() interceptás requests y respondés con datos mockeados: tests rápidos y deterministas sin backend real. Para no loguearte en cada test, guardás la sesión una vez con storage_state y la reusás vía la fixture browser_context_args. Menos flakiness, más velocidad.

Python 
# Mockeá una API para que el test sea rápido y determinista (sin backend real).
import json

page.route(
    "**/api/orders/42",
    lambda route: route.fulfill(
        status=200,
        content_type="application/json",
        body=json.dumps({"total": 250, "status": "PAID", "items": ["book"]}),
    ),
)
page.goto("/orders/42")
expect(page.locator(".order-total")).to_have_text("250")

# Reutilizá una sesión logueada entre tests con storage_state:
#   1) Guardala una vez tras loguearte: context.storage_state(path="auth.json")
#   2) Reutilizala con la fixture browser_context_args: {"storage_state": "auth.json"}# Mock an API so the test is fast and deterministic (no real backend).
import json

page.route(
    "**/api/orders/42",
    lambda route: route.fulfill(
        status=200,
        content_type="application/json",
        body=json.dumps({"total": 250, "status": "PAID", "items": ["book"]}),
    ),
)
page.goto("/orders/42")
expect(page.locator(".order-total")).to_have_text("250")

# Reuse a logged-in session across tests with storage_state:
#   1) Save it once after logging in: context.storage_state(path="auth.json")
#   2) Reuse it via the browser_context_args fixture: {"storage_state": "auth.json"}

CI + trace viewer

Donde Playwright brilla: en pytest.ini activás traces (--tracing retain-on-failure) y artefactos. Ante un fallo en CI, abrís el trace viewer con playwright show-trace y ves cada paso, el DOM y la red. Sumá reintentos y artefactos en el pipeline.

INI 
# pytest.ini — URL base, tracing y reintentos en CI para pytest-playwright.
[pytest]
addopts =
    --base-url http://localhost:3000
    --tracing retain-on-failure
    --output test-results
# Reejecutá tests flaky en CI (necesita el plugin pytest-rerunfailures):
#   --reruns 2# pytest.ini — base URL, tracing and CI retries for pytest-playwright.
[pytest]
addopts =
    --base-url http://localhost:3000
    --tracing retain-on-failure
    --output test-results
# Re-run flaky tests in CI (needs the pytest-rerunfailures plugin):
#   --reruns 2
YAML 
# .github/workflows/e2e.yml — corré Playwright en cada pull request.
- run: pip install pytest-playwright
- run: playwright install --with-deps
- run: pytest --tracing retain-on-failure
- uses: actions/upload-artifact@v4
  if: always()
  with:
    name: test-results
    path: test-results/
