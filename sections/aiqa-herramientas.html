Skills, hooks y agentes

Como AI QA Engineer no solo escribís prompts: armás skills, hooks y agentes que hacen el trabajo repetible por vos. Acá va el cómo de cada uno aplicado a QA.

Las definiciones de skill, hook, agente, modelo, MCP y RAG viven en Conceptos clave. Acá nos enfocamos en cómo crearlos y usarlos.

Crear una Skill: empaquetás las convenciones de tu equipo (framework, selectores, estilo de aserciones) en un archivo que el modelo carga siempre. Así cada test generado sale con tus estándares sin re-explicarlos en cada prompt:

Markdown 
# Skill: generate-e2e  (las convenciones de tu equipo, reutilizadas cada vez)

Cuando te pidan escribir un test end-to-end:
- Usá Playwright + los Page Objects en src/pages/.
- Selectores: getByRole / getByTestId solamente — nunca CSS ni XPath.
- Una intención por test, aserciones web-first, cero esperas fijas.
- Mockeá la red con page.route(); nunca pegues al backend real.

# Un skill empaqueta este know-how para que cada test generado siga los
# mismos estándares — sin necesidad de re-explicarlos en cada prompt.# Skill: generate-e2e  (your team's conventions, reused every time)

When asked to write an end-to-end test:
- Use Playwright + the Page Objects in src/pages/.
- Selectors: getByRole / getByTestId only — never CSS or XPath.
- One intent per test, web-first assertions, zero fixed sleeps.
- Mock the network with page.route(); never hit the real backend.

# A skill packages this know-how so every generated test follows the
# same standards — no need to re-explain them in each prompt.

Usar un Hook: enganchás un comando tuyo a un evento del agente. Ejemplo típico de QA: después de que la IA edita un test, correr lint + ese test automáticamente, para que un cambio roto no pase:

JSON 
// A HOOK runs YOUR command automatically on an agent event. Here: after
// the agent edits any test file, lint it and run it — so a broken change
// can never slip through, no matter what the model does.
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command",
            "command": "npx eslint \"$FILE\" && npx playwright test \"$FILE\"" }
        ]
      }
    ]
  }
}

Correr un Agente: le das un objetivo y itera solo (escribir → correr → leer el fallo → corregir) usando las tools. Para más confianza, un segundo agente revisor intenta refutar el test:

Text 
Bucle de agente — autónomo "escribir → correr → leer la falla → corregir":

  1. Leé la historia de usuario + criterios de aceptación.
  2. Generá el test de Playwright (usando el Skill del equipo de arriba).
  3. Corrélo vía el servidor MCP de Playwright.
  4. Si falla: leé el error + traza, ubicá la causa, parcheá el test.
  5. Repetí hasta que esté en verde, luego abrí un PR.

Variante multi-agente (mayor confianza):
  - Agente Escritor  -> redacta el test.
  - Agente Revisor -> intenta REFUTARLO: "¿puede pasar incluso si la app está
    rota?" Solo los tests que sobreviven la revisión se commitean.Agent loop — autonomous "write → run → read failure → fix":

  1. Read the user story + acceptance criteria.
  2. Generate the Playwright test (using the team Skill above).
  3. Run it via the Playwright MCP server.
  4. If it fails: read the error + trace, locate the cause, patch the test.
  5. Repeat until green, then open a PR.

Multi-agent variant (higher confidence):
  - Writer agent  -> drafts the test.
  - Reviewer agent -> tries to REFUTE it: "can this pass even if the app is
    broken?" Only tests that survive the review get committed.

Conectar con MCP: le das herramientas reales (navegador, GitHub, base de datos) para que el agente las use de forma estándar. Con esto puede correr la suite y leer el reporte de verdad:

JSON 
// Dale a la IA herramientas reales vía servidores MCP (puede manejar un navegador, leer
// el DOM/árbol de accesibilidad en vivo, abrir PRs, consultar tu issue tracker).
{
  "mcpServers": {
    "playwright": { "command": "npx", "args": ["@playwright/mcp@latest"] },
    "github": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-github"] }
  }
}// Give the AI real tools via MCP servers (it can drive a browser, read
// the live DOM/accessibility tree, open PRs, query your issue tracker).
{
  "mcpServers": {
    "playwright": { "command": "npx", "args": ["@playwright/mcp@latest"] },
    "github": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-github"] }
  }
}
