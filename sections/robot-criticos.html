Robot Framework

Casos críticos

Los escenarios que toda app real necesita — APIs, montos, documentos legales y seguridad — resueltos en este framework. (El login ya fue tu primer test, más arriba.)

API testing (CRUD + auth)

Probás la API directamente, cubriendo todos los verbos: creás (POST → 201), leés (GET → 200), actualizás (PATCH/PUT → 200) y borrás (DELETE → 204, y un GET posterior da 404). Validás el contrato de cada respuesta y la autenticación: sin token, 401; nunca un 200 silencioso.

Robot Framework 
*** Settings ***
Library    RequestsLibrary

*** Test Cases ***
Orders CRUD contract
    Create Session    api    https://api.example.com    headers=${AUTH}
    # CREATE (POST) -> 201
    ${created}=    POST On Session    api    /orders    json={"items": ["book"]}
    Status Should Be    201    ${created}
    ${id}=    Set Variable    ${created.json()}[id]
    # READ (GET) -> 200
    ${got}=    GET On Session    api    /orders/${id}
    Should Be Equal As Strings    ${got.json()}[status]    NEW
    # UPDATE (PATCH) -> 200
    ${upd}=    PATCH On Session    api    /orders/${id}    json={"status": "PAID"}
    Should Be Equal As Strings    ${upd.json()}[status]    PAID
    # DELETE -> 204, después GET 404
    DELETE On Session    api    /orders/${id}    expected_status=204
    GET On Session    api    /orders/${id}    expected_status=404*** Settings ***

Cuentas y recibos de pago

La matemática del recibo tiene que cerrar siempre: la suma de los ítems = subtotal, el impuesto exacto y subtotal + impuesto = total. Más los invariantes: nunca negativo, estado consistente con lo pagado.

Robot Framework 
# Montos — leé el recibo por HTTP y verificá las cuentas del dinero (en centavos).
${res}=    GET On Session    api    /receipts/9087
${r}=    Set Variable    ${res.json()}
Should Be Equal As Integers    ${r}[totalCents]    10890
Should Be True    ${r}[totalCents] == ${r}[subtotalCents] + ${r}[taxCents]
Should Be True    ${r}[totalCents] > 0# Amounts — read the receipt over HTTP and assert the money math (in cents).

Validación de documentos legales

Facturas, contratos o comprobantes: validás que estén los campos obligatorios, el formato del número, el estado (firmado) y que la fecha no sea futura.

Robot Framework 
# Validación de documento legal — campos requeridos y formato de una factura.
Go To    https://app.example.com/invoices/INV-2026-0042
${num}=    Get Text    css=.invoice-number
Should Match Regexp    ${num}    ^INV-\d{4}-\d{4}$
${tax_id}=    Get Text    css=.tax-id
Should Not Be Empty    ${tax_id}

Seguridad: autorización e IDOR

El control de acceso es crítico: el usuario A no debe poder leer la orden del usuario B con solo cambiar el id en la URL (eso es un IDOR). Debe responder 403, no 200.

Robot Framework 
# Seguridad — autorización/IDOR + XSS.
# El usuario A NO debe leer la factura del usuario B (403, no 200).
GET On Session    api    /invoices/INV-2026-0099    expected_status=403

# XSS: el payload se renderiza como texto, nunca se ejecuta.
Go To    https://app.example.com/search?q=<script>alert(1)</script>
Page Should Contain    <script>alert(1)</script># Security — authorization/IDOR + XSS.
