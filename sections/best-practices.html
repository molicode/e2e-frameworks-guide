Buenas prácticas

Cerramos con principios que aplican sin importar el framework o si usás AI o no. Son los hábitos que separan una suite confiable de un dolor de cabeza.

Principios que perduran

  • Esperá condiciones, no tiempo. Cero sleep fijos.
  • Selectores estables. Preferí roles, etiquetas y data-testid sobre css/xpath profundos.
  • Tests independientes. Cada uno crea y limpia sus propios datos; el orden no debe importar.
  • Un test, una intención. Nombres claros y un objetivo por test.
  • Respetá la pirámide. Pocos E2E, muchos unit.
  • Que falle bien. Un test que nunca puede fallar no protege nada.
  • La AI asiste, vos validás. Revisá y entendé todo lo que entra al repo.

Próximos pasos

  1. Elegí un framework y resolvé el caso VerifyOrder de esta guía de punta a punta.
  2. Integralo a CI (GitHub Actions, GitLab CI…) para que corra en cada pull request.
  3. Adoptá el patrón Page Object o helpers para no repetir selectores por toda la suite.
  4. Sumá AI a tu flujo: usala para generar casos y revisar tests, siempre validando el output.
  5. Contribuí a esta guía: es open source. Agregá un idioma, una sección o un ejemplo (ver el README).
Lo importante: la automatización no busca cero bugs, busca confianza para entregar seguido. Empezá chico, mantené verde y crecé desde ahí.
