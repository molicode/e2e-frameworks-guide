Ruta de aprendizaje

Ruta de aprendizaje

  1. Localizar elementos — Dominá los By: CSS sobre XPath siempre que puedas. Practicá selectores robustos.
  2. Esperas explícitas — El concepto más importante. WebDriverWait + ExpectedConditions. Evitá Thread.sleep.
  3. Runner + assertions — Integralo con JUnit5/TestNG (Java) o pytest (Python). Selenium conduce, no testea.
  4. Page Object Model — Refactorizá a POM antes de que la suite crezca. La diferencia entre mantenible e infierno.
  5. Grid y CI — Corré en paralelo con Selenium Grid o un servicio cloud, e integralo al pipeline.

Localizar elementos

Selenium localiza elementos con la clase By: By.ID, By.CSS_SELECTOR, By.XPATH… Usá find_element para uno y find_elements para una lista. Regla práctica: preferí CSS sobre XPath (más legible y rápido) y reservá XPath para buscar por texto visible.

Python 
# Selenium ofrece muchas estrategias de localización vía By. Preferí CSS sobre XPath.
driver.find_element(By.ID, "username")                    # por id
driver.find_element(By.CSS_SELECTOR, ".order-total")      # por CSS (preferido)
driver.find_element(By.CSS_SELECTOR, "[data-testid=pay]") # por atributo de test
driver.find_elements(By.CSS_SELECTOR, ".order-items li")  # una lista (¡plural!)

# XPath es potente pero frágil — reservalo para "buscar por texto visible":
driver.find_element(By.XPATH, "//button[text()='Pay']")# Selenium offers many locator strategies via By. Prefer CSS over XPath.
driver.find_element(By.ID, "username")                    # by id
driver.find_element(By.CSS_SELECTOR, ".order-total")      # by CSS (preferred)
driver.find_element(By.CSS_SELECTOR, "[data-testid=pay]") # by test attribute
driver.find_elements(By.CSS_SELECTOR, ".order-items li")  # a list (plural!)

# XPath is powerful but brittle — reserve it for "match by visible text":
driver.find_element(By.XPATH, "//button[text()='Pay']")

Esperas explícitas

Selenium no reintenta solo: si actuás antes de que el elemento exista, falla. La solución son las esperas explícitas: en Python, WebDriverWait(driver, 5).until(...) junto con expected_conditions (EC). Nunca uses un time.sleep fijo: es la causa número uno de flakiness.

Python 
# Esperas explícitas: esperá una CONDICIÓN, nunca un sleep fijo.
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

wait = WebDriverWait(driver, 5)
wait.until(EC.visibility_of_element_located((By.CSS_SELECTOR, ".welcome")))
wait.until(EC.element_to_be_clickable((By.CSS_SELECTOR, ".welcome")))

# Nunca hagas esto — un sleep ciego es la causa #1 de suites Selenium inestables:
# import time; time.sleep(5)# Explicit waits: wait for a CONDITION, never a fixed sleep.
from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

wait = WebDriverWait(driver, 5)
wait.until(EC.visibility_of_element_located((By.CSS_SELECTOR, ".welcome")))
wait.until(EC.element_to_be_clickable((By.CSS_SELECTOR, ".welcome")))

# Never do this — a blind sleep is the #1 cause of flaky Selenium suites:
# import time; time.sleep(5)

Runner + assertions

Selenium solo conduce el navegador; las afirmaciones las pone un test runner. En Java se combina con JUnit 5 o TestNG; en Python con pytest. El runner aporta estructura (setup/teardown), assertions y reportes.

Python 
# Selenium maneja el navegador; pytest aporta estructura + aserciones.
import pytest
from selenium import webdriver
from selenium.webdriver.common.by import By


@pytest.fixture
def driver():
    d = webdriver.Chrome()
    yield d           # setup antes del test, teardown después
    d.quit()


def test_verify_order(driver):
    driver.get("https://shop.example.com/orders/42")
    total = driver.find_element(By.CSS_SELECTOR, ".order-total").text
    assert total == "250"# Selenium drives the browser; pytest provides structure + assertions.

Page Object Model

El Page Object Model (POM) encapsula los selectores y acciones de una página en una clase con métodos que revelan intención (order.total() en vez de un css suelto). Cuando el HTML cambia, tocás un solo lugar. Es la diferencia entre una suite mantenible y un infierno de selectores repetidos.

Python 
# order_page.py — un Page Object esconde los selectores tras métodos que revelan la intención.
from selenium.webdriver.common.by import By


class OrderPage:
    def __init__(self, driver):
        self.driver = driver

    def open(self, order_id):
        self.driver.get(f"https://shop.example.com/orders/{order_id}")

    def total(self):
        return self.driver.find_element(By.CSS_SELECTOR, ".order-total").text

    def status(self):
        return self.driver.find_element(By.CSS_SELECTOR, ".order-status").text


# El test se lee como una oración y sobrevive a los cambios del DOM:
order = OrderPage(driver)
order.open(42)
assert order.total() == "250"# order_page.py — a Page Object hides selectors behind intent-revealing methods.

Grid y CI

Selenium Grid te deja correr los tests en navegadores remotos y en paralelo: usás webdriver.Remote(command_executor=...) apuntando a un hub en vez de a un navegador local. En CI se levanta el Grid (por ejemplo, con Docker) y se ejecuta la suite en cada pull request.

Python 
# Ejecutá contra un Selenium Grid remoto en vez de un navegador local.
from selenium import webdriver

driver = webdriver.Remote(
    command_executor="http://grid.internal:4444/wd/hub",  # el hub del Grid
    options=webdriver.ChromeOptions(),
)

# En CI normalmente arrancás el Grid con Docker primero:
#   docker run -d -p 4444:4444 selenium/standalone-chrome# Run against a remote Selenium Grid instead of a local browser.
